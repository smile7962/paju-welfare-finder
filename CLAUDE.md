# Core Rules

- Think first. If ambiguous, ask; never assume.
- Minimal code only. No extra abstraction, no speculative features.
- Surgical edits. Touch only lines related to the request.
- Reuse before creating. Check existing code first; no duplicate logic.
- Small steps. Keep each change small; big tasks need an approved plan first.
- Verify before done. Confirm it actually runs before claiming completion.
- Beginner user. Explain jargon simply. Confirm before risky/irreversible actions (delete, deploy, DB changes).
- Commit habit. Suggest a commit after each working unit. Korean commit messages, describe what/why. Never commit broken code.
